# 원랜디 학습 AI

제공된 **ORDR 2.323[R] 맵의 훈련용 복사본**과 Python/PyTorch를 연결하는 초기 심층 강화학습 구현이다. 원본 맵을 수정하지 않는다.

AI가 실제 게임의 상태를 읽고 행동을 선택한 뒤, 그 결과에 따라 신경망을 갱신한다. 미리 정해 놓은 조합 순서를 반복하는 매크로나, 별도로 만든 간이 디펜스 시뮬레이터가 아니다. 다만 **이 코드가 있다는 것과 이미 원랜디를 잘하는 모델이 있다는 것은 다르다.** 장시간 학습한 클리어 모델을 제공하는 프로젝트는 아니다.

- 게임 규칙: [플레이 가이드](docs/ORDR_2.323R_플레이_가이드.md)
- 원본 분석: [분석 근거](docs/ORDR_2.323R_분석_근거.md)
- 연결 구조: [.omo/jass-bridge-notes.md](.omo/jass-bridge-notes.md)

## 현재 학습 범위

처음에는 **플레이어 0, 혼자 하는 오프라인 게임, 쉬움, 추가 모드 없음**을 대상으로 한다.

### AI가 보는 것

게임 스크립트의 실제 값을 읽는다.

- 라운드, 골드, 목재, 특성포인트.
- 라인 몬스터 수와 제한, 남은 데스 카운트.
- 스토리 단계와 미처리 보스 수.
- 살아 있고 보이는 아군의 종류별 수.
- 실제 승리·패배 플래그.
- 기록지침 창: 항해목표 10개의 달성·실패와 진행도, 항로개척 퀘스트 3칸, 고른 항법지침과 그 효과(아래 "기록지침 근거표").

현재 정책 사전(스키마 3)에는 유닛 종류 467개와 행동 590개가 있다(568개 뒤에 항해목표 공격 6개, 코드 331~336, 그 뒤에 숨은 보물상자 탐색 16개, 행동 번호·코드 574~589). 유닛 사전에는 관측 시 수가 0인 항목도 포함되며, 467개 모두가 독립된 플레이 캐릭터라는 뜻은 아니다. 스키마 2의 행동 251개(기본 8, 조합 237, 건물 6)는 번호·순서·내용을 그대로 두고, 원본 맵의 나머지 플레이어 입력 317개를 맨 뒤(행동 번호 251~567, 맵에 보내는 코드 14~330)에 붙였다. 유닛 사전은 스키마 2와 같다(`tests/test_inputs.py`가 앞 251개와 유닛 사전을 스키마 2 해시와 대조한다). 관측 벡터는 스칼라 10개, 유닛 수 467개 뒤에 기록지침 특징 87개, 숨은 보물상자 특징 34개가 붙어 598차원이다(`observation.input_size`). 행동 사전이 바뀌면 이전 체크포인트는 호환성 검사에서 거부된다(스키마 2의 `runs/` 모델 포함). 체크포인트 파일은 지우지 않는다.

### AI가 할 수 있는 것

- 대기.
- 랜덤위습 한 기를 일반 소환, 목재 도박, 도움소 마나 구역으로 이동.
- 랜덤위습 전부를 한 번에 일반 소환 구역으로 이동(행동 7).
- 진화체위습 사용. 진화체는 라인몹 152마리를 잡으면 시작 위치(라인 고리 한가운데)에서 활성화되는데, 그 자리는 어느 라인몹에도 닿지 않아 그대로 두면 끝까지 서 있기만 한다. 그래서 브리지는 매 행동 전에 시작 위치에 서 있는 대기 중인 전투 유닛을 소환 구역 `aP[0]`으로 공격 이동시킨다(`ORDAI_Deploy`). 실제 게임 29판에서 진화체(아론 - 특별)가 5라운드부터 끝날 때까지 시작 위치에 서 있는 것을 확인했고, 시뮬레이터 8판에서도 같았다(배치 전 평균 약 440스텝 정지, 배치 후 1~3스텝 안에 이동).
- 라인에서 병력 한 기를 스토리로 보내거나 스토리에서 한 기를 회수.
- 실행 가능한 원본 조합 237개를 시도.
- 도박소·강화소 건물 행동 6개(행동 번호 245~250, 맵에 보내는 코드 8~13). 비용·재고·조건은 원본 `war3map.w3u`/`war3map.w3q`와 `war3map.j`에서 확인했고 `tests/test_shop_actions.py`가 맵 파일과 다시 대조한다.

| 행동 | 건물 | 비용 | 마스크 조건 |
|---|---|---|---|
| 돈 도박 하급 | 도박소 1 | 10골드, 75% 확률 10~50골드 | 도박소 2로 바뀌기 전 |
| 돈 도박 고급 | 도박소 1 | 500골드, 70% 확률 500~4500골드 | 10라운드 보스 처치(`R009`) 후, 도박소 2 전 |
| 흔함류 업그레이드 | 강화소 1 | 3 + 2×현재 레벨, 최대 7 | 최대 레벨 전 |
| 특별 업그레이드 | 강화소 1 | 5 + 5×현재 레벨, 최대 15 | 최대 레벨 전 |
| 희귀 업그레이드 | 강화소 1 | 10 + 20×현재 레벨, 최대 16 | 최대 레벨 전 |
| 고급 유닛 생성 | 도박소 2 | 5000골드, 무작위 희귀 1기(재고 1) | 돈 도박 고급으로 35000골드를 얻어 도박소 2가 생긴 뒤(`R01M`), 스토리 5. 스릴러바크 파괴(`R01N`) 후 |

맵은 돈 도박 고급으로 얻은 골드를 누적해 35000이 되면 도박소 1을 도박소 2로 바꾼다. 이때 돈 도박 하급·고급은 더 팔지 않는다. 마스크는 골드와 해금만 본다. 재고는 맵이 검사하고, 팔지 않으면 행동이 거부된다. 구매·연구는 게임의 실제 판매·연구 시작 이벤트가 올 때만 수락으로 기록한다.

조합은 **원래 스킬을 실제로 시전하거나 원래 채팅 명령의 처리 함수를 실행**한다. 재료·비용·쿨타임·조건 검사를 건너뛰어 유닛을 무료로 주지 않는다. 조합 표시용 테이블에만 있는 29개 항목은 행동 사전에서 제외했다.

#### 원본 플레이어 입력 317개(스키마 3)

빌드할 때 `war3map.j`의 입력 등록표(`Jos` 판매·훈련·능력·선택 처리, `KdR` 동기화, `kIs` 구역 진입, `FMv` 채팅)와 오브젝트 데이터(`war3map.w3u`/`w3a`/`w3q`/`w3t`)에서 읽는다(`inputs.py`, `objectdata.py`). 브리지 입력 표(`bridge_actions.j`의 생성 블록)가 맵에서 다시 만든 표와 다르면 `ord-ai build`가 거부한다. 표를 다시 만들 때는 `uv run python -m ord_ai.build "ORDR_S2_2.323[R].w3x"`를 쓴다. 모든 행동은 원래 입력 경로를 거치므로 비용·재고·쿨타임·마나·처리 함수의 조건은 맵이 그대로 적용한다. 결과를 직접 주는 행동은 없다.

대상 선택 규칙(정책은 대상을 고르지 않는다):

- 시전 유닛: 능력이 있고(레벨 > 0) 쿨타임이 끝난, 살아 있고 숨겨지지 않은 Player(0) 유닛(건물 포함). 오래된 유닛(핸들 번호가 작은 순)부터 주문을 받아 주는 첫 유닛이 시전한다. 마나 부족 등은 맵과 엔진이 거부한다.
- 적 대상 능력(허용 대상에 enemy/neutral만 있음): 사거리(`aran`, 99999 이상이면 제한 없음) 안에서 가장 가까운, 살아 있고 보이며 무적이 아닌 적 유닛(건물 제외).
- 지점 능력: 위 규칙의 적 위치. 탐색 `A05D`는 시전자 위치.
- 아군 대상 능력(허용 대상에 player/friend/allies/self가 있거나 적 표시가 없음): 사거리 안의 자기 유닛 중 가장 강한 유닛(점수 `upoi`, 기본 공격력, 오래된 순). 허용 대상에 `self`가 없으면 시전자는 제외.
- 처리 함수의 대상 검사를 따른 예외:

구역 이동은 위습 발판이면 그 위습 중 가장 오래된 한 기, 귀환·이동 발판과 포네그리프면 스토리 보내기와 같은 규칙(가장 강한 한가한 병력)으로 움직인다. 행동 번호가 1000 미만(14~999)이라 규칙 교사 봇(`teacher.py`)은 아직 새 행동을 고르지 않는다.

## 학습 방식

**행동 마스크가 있는 Advantage Actor-Critic(A2C)**를 사용한다.

1. 관측을 고정된 수치 벡터로 변환한다.
2. 128차원 은닉층 두 개를 가진 신경망이 행동 확률과 상태 가치를 출력한다.
3. 보유 유닛·골드·목재가 부족한 행동을 우선 마스킹한다.
4. 행동을 맵에 보내고 1게임초 후의 결과를 받는다.
5. 라운드·스토리 진전, 보스 처리, 승패, 거부된 행동 등으로 보상을 계산한다.
6. 기본 32개 전이를 모아 정책과 가치망을 갱신한다.

마스크는 모든 특수 조건을 복제하지 않는다. 남은 조건은 원본 맵이 최종 판단하며, 실패한 시도는 `action_ok=0`으로 학습 기록에 남는다. 이동 명령의 성공은 도착·소모 완료와 다르다. 유닛이 아직 이동 중일 수 있다.

조합만 했다는 이유로 양의 보상을 주지는 않는다. 진행이나 전투 결과에 도움이 되는 조합을 학습하도록 설계했다. 현재 보상 설계와 네트워크가 최적이라는 뜻은 아니며, 실제 평가 결과에 따라 조정해야 한다.

### 시뮬레이터 학습

학습은 시뮬레이터(`D:/OrandOverlay/local-tools`, 원작 동일화 세션 담당)에서 하고 실제 Warcraft는 시험장으로만 쓴다. 시뮬레이터는 원본 `war3map.j`와 이 저장소의 브리지 JASS를 그대로 실행하고 실제 게임과 같은 `state.txt`를 돌려준다. 그래서 관측(`features`), 행동 사전(`build/catalog.json`), 마스크(`available_actions`), 보상, 체크포인트 형식이 실제 게임 경로와 같고, 시뮬레이터에서 만든 체크포인트를 실제 게임에서 그대로 쓸 수 있다. **시뮬레이터 결과는 실제 게임 성능이 아니다.**

```powershell
uv run ord-ai build            # 브리지·행동 사전을 바꾼 뒤에는 항상 먼저
uv run ord-ai sim-demos        # 규칙 교사 봇 시범 기록(runs/sim-demos)
uv run ord-ai sim-imitate      # 모방학습(runs/sim-imitation)
uv run ord-ai sim-train        # 커리큘럼 강화학습 미세조정(runs/sim-rl, 이어 하기 가능)
uv run ord-ai sim-eval runs/sim-eval/rl.jsonl --checkpoint runs/sim-rl/best --difficulty 1
```

- 설정은 작업 폴더의 `sim.json`(없으면 기본값)에서 읽는다. 환경 수(`envs`), 시범 판 수, 학습률, 강화학습 스텝 수, 초반 모방 혼합(`bc_every`, `bc_until`) 등이 있다(`simtrain.SimConfig`).
- 단계마다 `build/sim/d<난이도>[i]` 서버 폴더를 만든다. 시뮬레이터 실행 파일은 복사하고 맵 데이터는 연결만 하며, 브리지 파일만 이 저장소의 현재 파일로 쓴다. 바뀐 파일만 다시 쓰므로 학습 중에 같은 단계로 평가를 따로 돌려도 된다. 시뮬레이터 폴더는 읽기만 한다.
- 강화학습은 두 가지다. 기본 `sim.json`은 환경마다 32스텝(또는 판 끝)마다 갱신하는 A2C, `sim-ppo.json`은 `"algorithm": "ppo"`(128스텝 모음, GAE, 잘라낸 목표, 4에폭)다. 체크포인트 형식은 같아서 어느 쪽이든 `real-play`에 그대로 넣는다. 초반(`bc_until`, 3M스텝까지)에는 갱신 4번마다 교사 시범 한 묶음으로 모방 한 번을 섞어 정책이 무너지지 않게 한다.
- 교사는 사용자가 알려준 운영(돈 도박, 강화, 물품 지원, 고급 유닛 생성)만 고정 규칙으로 쓴다. 항법지침·항해목표·항로개척 같은 나머지 행동은 강화학습이 스스로 찾는다. 모방학습은 목표의 `imitation_smoothing`(기본 설정 0.1)만큼을 허용된 모든 행동에 고루 나눠 교사가 안 쓴 행동도 확률이 0 근처로 굳지 않게 하고, 강화학습은 엔트로피 보너스 `entropy_weight`(0.005)로 탐색을 유지한다. 0.02는 어려움에서 평균 라운드가 27.9에서 23.9로 떨어져(건물 행동 판당 44→94회) 낮췄다(`runs/sim-rl-v3a`).
- 보상: 라운드·스토리·보스 진행, 라인 압박 변화, 거부된 행동 -0.05, 패배 -10, 클리어는 유닛 카운트 0이면 +20·적이 남으면 +10. 특정 행동을 유도하는 보상은 넣지 않는다.
- 기록: `episodes.jsonl`(판마다 단계·라운드·결과·유닛 카운트 0 클리어 여부), `curriculum.json`(현재 단계·승급 기록), `imitation.jsonl`(에폭별 손실·교사 일치율), 체크포인트(`policy.safetensors`, `metadata.json`, `catalog.json`), 최근 64판 평균 라운드가 가장 높았던 모델은 `best/`.

Windows, Python 3.12 이상, `uv`, 설치 및 로그인 가능한 Warcraft III가 필요하다. 현재 컴퓨터에서는 RTX 3080 Ti 12GB와 PyTorch CUDA를 확인했다.

작업 폴더에서:

```powershell
uv sync
uv run ord-ai doctor
```

`uv.lock`에 의존성을 고정했다. CUDA 12.8용 PyTorch를 받으므로 첫 설치에는 수 GB의 다운로드가 발생한다. `device`를 `cpu`로 설정하면 CPU에서도 실행할 수 있다.

## 훈련 맵 준비

원본 파일을 작업 폴더에 둔다.

```text
ORDR_S2_2.323[R].w3x
```

다음 명령은 원본의 SHA-256이 분석한 파일과 같은지 확인하고 별도 복사본을 만든다.

```powershell
uv run ord-ai build
```

결과:

```text
build/ORDR_AI_2.323R.w3x
build/war3map.j
build/catalog.json
```

이 브리지는 해당 버전의 함수·변수·유닛 ID에 연결되어 있으므로 다른 버전의 맵을 임의로 넣으면 안 된다.

### 게임의 맵 목록에 설치

PowerShell에서:

```powershell
$docs = [Environment]::GetFolderPath("MyDocuments")
uv run ord-ai build --output "$docs\Warcraft III\Maps\Download\ORD_AI\ORDR_AI_2.323R.w3x"
uv run ord-ai init "$docs\Warcraft III\CustomMapData\ORD_AI"
```

`training.json`이 생성된다. 문서 폴더가 OneDrive 등으로 이동되어 있다면 반드시 게임이 실제로 사용하는 문서 폴더를 지정한다.

맵의 로컬 파일 통신을 활성화한다. 이 컴퓨터에는 작업 중 아래 설정을 적용했다.

```powershell
reg add "HKCU\Software\Blizzard Entertainment\Warcraft III" /v "Allow Local Files" /t REG_DWORD /d 1 /f
```

이 설정은 맵 원본을 수정하지 않는다. 로컬 파일 접근을 다시 끄려면 값을 `0`으로 바꾼다.

```powershell
uv run ord-ai launch
```

   이 명령은 Battle.net 앱을 잠시 종료한 뒤 Warcraft III의 "추가 명령줄 인수"에 훈련 맵 경로를 넣고 게임을 실행한다. 실행 후에는 앱을 다시 종료해 원래 인수로 되돌린다. 실행 도중 강제 종료하면 Battle.net 앱의 게임 설정에서 추가 명령줄 인수를 직접 지워야 한다. `Warcraft III.exe -loadfile`로 직접 실행하면 Reforged가 실행할 때마다 인증을 요구한다.
3. 플레이어 0만 사람으로 두고 시작한다. 다른 사람과 함께하는 방에서 사용하지 않는다.
4. 맵을 불러온 뒤 원본 난이도 선택을 직접 진행하지 말고 아래 명령을 실행한다.

```powershell
uv run ord-ai train
```

브리지가 원본 선택 이벤트로 쉬움·기본 모드를 시작한다. 연결이 정상이라면 라운드·보상·손실값이 출력되고 `runs/ordr/transitions.jsonl`에 실제 전이가 쌓인다.

별도 설정 파일을 사용할 때는 **위치 인자가 아니라 `--config` 옵션**을 쓴다.

```powershell
uv run ord-ai train --config training.json
uv run ord-ai inspect --config training.json
```

### 설정에서 주로 바꾸는 항목

| 항목 | 의미 |
|---|---|
| `steps` | 이번 실행에서 수집할 전이 수. 기본 1,024 |
| `rollout` | 한 번의 신경망 업데이트에 모을 전이 수. 기본 32 |
| `timeout` | 게임 응답을 기다리는 실제 시간의 상한 |
| `device` | `auto`, `cuda`, `cpu` |
| `output` | 모델과 학습 기록 저장 폴더 |
| `resume` | 이어서 학습할 체크포인트 폴더. 처음에는 `null` |
| `training_map` | 설치된 훈련 맵 경로. 지정하면 판이 끝날 때마다 Warcraft를 닫고 Battle.net으로 다시 연다 |

### 자동 재시작과 창 포커스

`training_map`을 지정하면 사람 없이 여러 판을 이어 돌릴 수 있다.

- 판이 끝나면(승리·패배) Warcraft를 닫고 Battle.net으로 다시 연다. 맵 안의 `RestartGame`은 실제 게임에서 검은 화면으로 멈춰서 쓰지 않는다.
- 재시작이 응답하지 않으면 최대 3번 다시 연다. 판 도중 게임이 멈추면 모은 경험으로 학습한 뒤 다시 연다.
- 혼자 하는 게임은 로딩이 끝나면 "아무 키나 누르세요"에서 멈춘다. 맵의 로딩 화면 설정을 바꿔도 이 대기는 없어지지 않았다(실제 게임에서 확인).
  - 맵이 응답할 때까지 2초마다 Warcraft 창에 스페이스를 메시지로 보낸다. 다른 창이 맨 앞에 있어도 이 키로 로딩 화면이 넘어가는 것을 실제 게임에서 확인했고(브라우저가 맨 앞일 때 2초 안에 통과), 창 포커스는 옮기지 않는다.
  - 로딩 중에 보낸 키는 무시되고, 로딩이 끝난 뒤의 키로 넘어간다.
- 게임을 새로 열 때 Battle.net과 Warcraft 창이 각각 2초 안팎으로 앞에 나온 것을 측정했다. Battle.net이 창을 띄우므로 이 쪽에서 막지 못한다.
- 강제 종료하면 Battle.net의 추가 명령줄 인수가 남을 수 있다. 다음 실행이 이를 알아보고 되돌리지만, 그 전에 직접 게임을 켜면 훈련 맵이 열린다.

게임 자체는 실시간으로 실행된다. GPU가 빨라도 게임 경험 수집이 빨라지는 것은 아니며, 현재 구현은 여러 게임을 병렬 실행하거나 수십 배속 시뮬레이션하지 않는다. 1,024스텝은 고수 모델을 만드는 학습량이 아니라 실행을 확인할 수 있는 초기 설정이다.

- 한 프로세스에서 게임 중 맵 재오픈(화면 깨짐)이 나면, 다음 판은 워크3를 다시 띄우지 않고 맵의 RestartGame으로 연다(후보 A, `texture-patch.md`). 응답이 없으면 다시 띄우기로 돌아간다.
- 모방학습과 강화학습은 시뮬레이터에서만 한다(`sim-imitate`, `sim-train`). 실제 게임은 `real-play`로 시험만 한다.
- 행동 7(위습 전부 소환)은 실제 게임에서 수락됐다. 게임 속도를 '가장 빠름'으로 올리는 설정은 실제 스텝 간격이 줄어들지 않았다. 엔진이 보통 속도로 되돌리는 것으로 보인다.

## 저장과 이어 하기

출력 폴더:

```text
policy.safetensors   신경망 가중치
metadata.json        알고리즘·사전 지문·이번 실행 전이 수
catalog.json         해당 모델의 관측/행동 사전
transitions.jsonl    실제 게임의 행동·보상·진행 기록
```

`Ctrl+C`나 연결 오류가 발생해도 종료 처리에서 마지막 가중치를 저장한다. 연결이 전혀 되지 않았다면 `steps=0`인 **미학습 모델**이 저장될 수 있으므로 파일 존재만으로 학습 성공을 판단하면 안 된다.

이어 학습하려면 `training.json`의 `resume`을 체크포인트 폴더로 지정하고 다시 `train`을 실행한다. **현재는 가중치만 이어 받고 Adam의 모멘텀 상태와 이전 rollout은 재개하지 않는다.** `resume=null`은 새 모델로 시작한다.

가중치를 갱신하지 않고 플레이만 하려면:

```powershell
uv run ord-ai play
```

`resume`에 모델 경로가 있어야 한다. 현재 `play`도 정책 분포에서 행동을 샘플링한다. 다른 버전이나 다른 순서의 행동 사전은 체크포인트 호환성 검사에서 거부한다.

### 시뮬레이터 대조용 실게임 기록

```powershell
uv run ord-ai record --episodes 11
```

규칙 교사 봇이 실제 게임을 11판 플레이하고 `runs/c2-teacher/transitions.jsonl`에 기록한다. 학습은 하지 않는다. 관측·행동·보상은 학습과 같고, 각 줄에 다음이 더 붙는다.

| 필드 | 뜻 |
|---|---|
| `game_time` | 상태를 내보낸 시점의 게임 시간(초). 게임이 진행될 때만 흐르는 타이머 기준 |
| `gv` | 그 시점의 맵 난수 상태 `Gv` |
| `gv_main` | 각 판 첫 줄에만. 맵 초기화 직후의 `Gv`(0이면 첫 추첨 때 정해진다) |
| `units` | 플레이어 0의 보이는 유닛마다 `[유닛 타입, x, y, 현재 명령 ID]` |
| `spawned` | 이 스텝에 새로 생긴 유닛 타입(위습 제외) |
| `pool_draws` | 이 스텝에 진화로 뽑힌 유닛 타입 |

`train`의 기록에도 같은 필드가 붙는다. 이 필드는 정책 입력에 쓰지 않는다.

새 기록은 `--output`으로 다른 폴더에 쓴다(`runs/c2-teacher`는 보존한다). 타격 단위 이벤트까지 남기려면 기록 빌드를 설치한다. 관측·행동·마스크는 일반 브리지와 같고, 시뮬레이터는 계속 일반 브리지를 쓴다.

```powershell
$docs = [Environment]::GetFolderPath("MyDocuments")
uv run ord-ai build --kind record --output "$docs\Warcraft III\Maps\Download\ORD_AI\ORDR_AI_2.323R.w3x"
uv run ord-ai record --episodes 4 --output runs/c2-events
```

`<output>/events.jsonl`은 상태를 내보낼 때마다 한 줄이다(`events.CombatEvents`). 직전 내보내기 이후의 이벤트가 들어 있고, `episode`·`sequence`로 `transitions.jsonl`의 줄과 이어진다.

| 필드 | 뜻 |
|---|---|
| `game_time`, `gv` | 내보낼 때의 브리지 시계(게임 초)와 `Gv` |
| `attacks` | 공격(`EVENT_PLAYER_UNIT_ATTACKED`, 모든 플레이어)마다 `time`, `gv`, `actor`(공격자), `target`(대상). 유닛은 `handle`·`raw_id`·`owner`(플레이어 번호) |
| `deaths` | 죽음마다 `time`, `gv`, `actor`(죽인 유닛, 없으면 handle 0·owner -1), `target`(죽은 유닛) |
| `damage` | 피해를 입은 유닛마다 합계: `first_time`(첫 타격 시각), `target`, `amount`(피해 합), `hits`, `life`·`max_life`(내보낼 때). 보스 피해량은 보스 유닛 타입의 줄이다 |
| `dropped` | 한 내보내기에 1500개를 넘어 버려진 공격·죽음 수 |

게임 중에 Warcraft III가 맵 파일을 다시 열면(War3Log `Opening mod`) 그 게임 시간·시각·로그 줄을 `display_breaks.jsonl`에 남긴다. `-loadfile`로 연 맵에서는 게임 시작 약 17분 뒤 래더 맵 10개를 다시 열면서 맵에 들어 있는 모델이 모두 로드에 실패했다(유닛이 안 보이고 선택되지 않음, 2026-09-29 사람 기록 2판). 게임 로직과 브리지는 계속 돌았다.

교사 봇의 운영 순서(위에서부터 먼저 해당하는 것):

1. 랜덤위습 소환, 흔함선택위습을 흔함 유닛으로 바꾸기(조합을 가장 많이 완성하는 흔함, 없으면 가장 적게 가진 흔함), 진화체위습 사용, 라인이 60% 이상 차면 스토리 병력 회수.
2. 고급 유닛 생성(판당 한 번).
3. 가능한 조합 중 재료·비용이 가장 큰 것.
4. 스토리로 병력 보내기(5라운드 이후, 라인이 한가할 때, 최대 2기).
5. 돈 도박 하급 → 흔함류 → 물품 지원(재고 2, 다 쓸 때까지) → 특별 → 희귀 업그레이드 → 돈 도박 고급.
6. 대기.

거부된 건물 행동(대개 재고 없음)은 재고가 다시 차는 시간만큼(하급 8스텝, 고급 7스텝) 건너뛴다. 에피소드 27부터 이 교사가 기록한다. 행동 번호 0~244는 이전 기록과 같은 행동이다.


`build/human_start.ps1`(이 PC용, `-Episodes N`으로 판 수)은 다음을 차례로 한다: AI 실게임 체인(`build/_real_chain.py`)과 돌고 있는 `ord-ai real-play`를 멈춘다 → Warcraft III를 끄고 → 현재 브리지로 사람 플레이 맵을 설치한다 → `ord-ai human-record`를 실행한다. 시뮬레이터 학습은 계속 돈다. AI 체인은 자동으로 다시 켜지지 않는다.

- `human-record`는 AI 판처럼 Battle.net으로 Warcraft III를 `-loadfile`로 켜서 맵을 바로 연다(2026-09-30부터, 메뉴 경유 없음). 켜져 있던 Warcraft III는 끄고, 끝나면 Battle.net 인자를 되돌린다(게임은 켜 둔다). 강제로 멈춘 이전 세션이 남긴 `-loadfile` 인자는 되돌리지 않는다. 창 복원·키 전송은 하지 않는다. `-loadfile`로 연 맵은 래더 맵 재오픈 뒤 모델이 깨질 수 있다. 그때는 아래처럼 그 뒤 줄을 시연에서 뺀다.
- 난이도·이세계 선택과 시작은 직접 한다. 맵이 자동으로 고르지 않고, 로딩 화면에도 키를 보내지 않는다. 맵이 시작될 때까지 30분(`--timeout`, 초)까지 기다린다.
- 게임이 WIN/LOSS로 끝나면 기록을 마친다. Warcraft III를 끄면 "Warcraft III가 꺼졌습니다"로 바로 끝난다.
- 게임 중 맵 파일 재오픈(위 `display_breaks.jsonl`)을 보면 알려 주고 기록한다. `human-demos`는 그 게임 시간부터의 줄을 빼고 만든다. 2026-09-29의 두 판(32·33)은 956.8초·981.7초부터 빠진다(사용 가능 1,840샘플).
- 줄은 스텝마다 바로 저장되므로 중간에 Ctrl+C로 멈춰도 그때까지의 기록은 남는다.
- 옵션: `--episodes`(기본 1판), `--output`(기본 `runs/human-play`), `--training-map`(기본 위 설치 경로).

`runs/human-play/transitions.jsonl`의 각 줄은 `ord-ai record`와 같은 필드에 다음이 붙는다. 게임 시작 전(WAITING) 줄은 쓰지 않는다.

| 필드 | 뜻 |
|---|---|
| `action` | 이 스텝의 첫 번째 사전 행동 코드, 아무것도 안 했으면 0(대기) |
| `human_inputs` | 이 스텝의 입력 전부(순서대로): `{"code": 코드 또는 null, "kind": 종류, "raw": 원래 식별자}` |
| `snapshot` | 이 스텝 시작 상태의 `state.txt` 원문(행동 사전이 커져도 관측·마스크를 다시 만들 수 있다) |
| `human_dropped` | 한 스텝에 1000개를 넘어 버려진 입력 수(있을 때만) |

맵이 잡는 입력과 코드(모두 플레이어 0):

| `kind` | 맵 이벤트 | 코드 | `raw` |
|---|---|---|---|
| `fusion` | 조합 성공(`Ys`, `Rs`) | 조합 코드 | 조합 능력 ID |
| `sell` / `train` / `research` | 판매·훈련 시작·연구 시작 | 8·9·13, 10~12와 입력 표 판매·훈련·연구 | 유닛/연구 ID와 건물 타입 |
| `spell` | 능력 효과(조합 능력 제외) | 입력 표 능력 | 능력 ID와 시전 유닛 타입 |
| `sync` | 맵이 쓰는 모든 동기화 접두어 | 항법·퀘스트 변경 | `접두어 데이터` |
| `chat` | 모든 채팅 | `-offline`/`-오프라인모드` → 330 | 채팅 원문 |
| `region` | 발판 진입(fY 1/4, CY 2, aY 3, nP 5, EY 6, 입력 표 발판 310~328) | 발판에 맞는 유닛이면 그 코드 | 유닛 타입, 안 맞으면 `pad<코드> <타입>` |
| `select` | 선택 처리기가 있는 유닛(e0FJ) 선택 | 329(Zv 안일 때) | 유닛 타입 |
| `attack` | 항해목표에 우클릭·공격 명령 | 331~336 | `명령 ID 목표번호 목표타입` |

사전에 없는 입력은 버리지 않고 `code: null`로 원래 식별자와 함께 남긴다. 일반 이동·우클릭, 선택 처리기가 없는 유닛 선택은 기록하지 않는다. 실패한 조합 시전은 남지 않는다(맵이 조합을 성공시킬 때만 기록).

모방 학습 데이터로 바꾸기:

```powershell
uv run ord-ai human-demos runs/human-play
```

`runs/human-play/demonstrations.pt`를 `sim-demos`와 같은 형식으로 쓴다. 사전 입력 하나마다 한 샘플(스텝 시작 상태의 관측), 입력이 없는 스텝은 대기 한 샘플이다. 사람이 실제로 한 행동이므로 그 샘플의 마스크에서는 항상 허용한다. 반환값은 판마다 할인 합이다.

일반 AI 맵(`ord-ai build`)은 이 기능과 무관하게 이전과 바이트 단위로 같다. 사람 플레이 맵만 `war3map_human.j`를 따로 쓰고 `catalog.json`은 다시 쓰지 않는다.

## 재시작과 통신

게임과 Python은 다음 파일을 사용한다.

```text
문서/Warcraft III/CustomMapData/ORD_AI/
  reset_<episode>.txt           Python → 맵, 재시작 명령
  cmd_<episode>_<sequence>.txt  Python → 맵, 행동 명령
  state.txt                     맵 → Python
  telemetry.txt                 맵 → Python, 재생 대조용 기록(정책은 읽지 않음)
  human.txt                     맵 → Python, 사람 플레이 맵만: 직전 내보내기 이후 입력
  boot.txt                      맵 재시작 식별 기록
```

- `episode`는 재시작마다 증가하고, `sequence`는 행동마다 증가한다.
- 명령마다 파일 이름이 다르다. Warcraft는 게임이 켜져 있는 동안 한 번 읽은 경로의 내용을 캐시하고, 파일을 고쳐 써도 다시 읽지 않는다. 실제 게임에서 측정해 확인했다. 캐시는 `RestartGame` 뒤에 비워진다. 맵은 다음 차례의 파일 이름만 읽고, Python은 응답을 받으면 그 파일을 지운다.
- 파일이 오래됐거나 마지막 `END` 레코드가 없으면 관측으로 사용하지 않는다.
- `state.txt`는 `STATE` 한 줄, 유닛 종류별 `UNIT` 줄, 기술 레벨 `TECH` 줄, `END` 순서다. `TECH`는 `GetPlayerTechCount` 값이다. 스키마 2의 7줄(`R00F`, `R00E`, `R008`, `R009`, `R01M`, `R01N`, `R00P`) 뒤에 마스크가 읽는 해금 기술 5줄(`R00G`, `R00H`, `R00I`, `R01S`, `R018`)과 연구 레벨 19줄이 붙어 모두 31줄이다(목록은 브리지 입력 표에서 만든다). 레코드 종류는 그대로라서 프로토콜 버전은 1이다. `TECH`는 행동 마스크만 쓰고 신경망 입력(관측)에는 넣지 않는다. 그 뒤에 기록지침 합성 행 33줄(`ZG00`~`ZN04`, 위 "기록지침 근거표")이 같은 `TECH` 형식으로 붙고, 이 행은 마스크와 관측 모두에 쓴다.
- 맵 코드 0~13은 기본·건물 행동, 14~999는 브리지 입력 표(`ORDAI_Input`, 331~336은 공격 `ORDAI_Attack`), 1000 이상은 조합 표 `cv`의 능력 코드다. 입력 표의 행동은 조합 경로로 가지 않는다.
- 유닛 업그레이드 연구 15개(`R000`·`R002`~`R004`·`R007`·`R00X`·`R013`~`R016`·`R019`·`R01V`·`R02C`·`R02O`·`R032`)는 맵 오브젝트 데이터에서 13레벨에 `R00H`를 요구한다(`greq` 13). `R00H`는 클리크(`o01W`)를 잡으면 생긴다(war3map.j 16978). 마스크(`catalog.RESEARCH_GATES`)는 12레벨에서 `R00H`가 없으면 이 연구를 막는다(2026-09-30 추가). 그전에는 마스크가 열려 있어 실게임·시뮬 모두 11~19라운드에 거절되는 `R007` 선택이 반복됐다(실게임 44판 702스텝 중 228번). 카탈로그·관측은 바뀌지 않아 체크포인트 호환성은 그대로다. 시뮬 탐욕 16판(PPO5 best, 시드 900000): 보통 수락률 64.1% → 83.7%, 10승(유닛 카운트 0 8) → 9승(6), 평균 라운드 46.3 → 45.3. 어려움 37.8(64판 게이트 전 37.9), 수락률 87.3%. 결과는 16판 범위에서 차이가 없다.
- 같은 명령을 두 번 적용하지 않는다.
- Python은 파일 변경 이벤트를 구독하며 고정 간격으로 상태 파일을 폴링하지 않는다.
- 재시작 명령은 실제 `RestartGame(false)`를 요청한다. 기존 게임 상태에 새 번호만 붙여 리셋한 척하지 않는다. `training_map`이 없을 때만 이 경로를 쓴다.
- 엔진 재시작이 실패하면 맵이 명시적으로 거부하거나 Python이 시간 초과로 중단한다. 실제 게임에서는 검은 화면으로 멈춘 적이 있어, 자동 재시작은 `training_map`으로 게임을 다시 여는 방식을 쓴다.
- 한 게임에는 Python 제어 프로세스 하나만 연결한다. 실행 중 `boot.txt`를 지우거나 명령 파일을 수동 편집하지 않는다.
